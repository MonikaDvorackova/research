## 2. What the literature already solves (and what it does not claim)
1. **Searching a fixed expression grammar**: SINDy family, PySR, DSR, AI Feynman, ProGED. Solved in the sense that, given a library that contains the generating terms and enough clean data, sparse/evolutionary search recovers them. PySR with a *broad* operator set subsumes most of "adaptive expansion" by simply including the operators.
2. **Larger libraries**: documented as increasing collinearity/noise sensitivity (SINDy-PI, weak-form papers motivate robustness). This phase reproduces that in §4.
3. **Hidden state**: SINDy-AE and deep delay autoencoders learn latent coordinates for passive data; E-SINDy provides ensemble variance as an active-learning signal. None of the sources read tests *which interventions* distinguish newly generated structural hypotheses with calibrated rejection of the current language.
4. **Distinct achievements** (the brief asked for them to be kept apart): *fixed-grammar search* (all of the above); *larger fixed grammar* (PySR-expanded, this study's `static_all`); *new operators* (not achieved by any method here — operators are only ever added by the designer, either to PySR's list or to the stage vocabularies); *hidden-variable discovery* (a leaky integrator state and a state-state interaction are among the stage vocabularies, so this is selection among designer-supplied options, not discovery of unforeseen variables); *new causal edge* (not tested); *structure revision* (L0 → expanded hypothesis via criticism trigger); *predictive equivalence without mechanism* (measured as the gap between L1 and L2).

## 3. Novelty threats (ranked)
1. **PySR with an expanded library / `static_all` search** — if a broad static grammar matches the adaptive loop, adaptive expansion is not an accuracy advantage. Result in doc 24: it matches or beats the loop on structure.
2. **E-SINDy / SINDy-PI / weak-SINDy** — covered by the baselines below, in my configurations.
3. **ProGED / DSR** — grammar- and neural-guided search not run; a fixed-grammar method with a prior over expansions is the closest conceptual rival to a staged closure.
4. **BED under misspecification (Rainforth et al.)** — explains why declared-class design fails out of class; the falsification design here is a simple instance, not a contribution.
5. **Deep delay autoencoders** — alternative route to a hidden state; not run.
Remaining gap, if any: the *composition* "calibrated rejection → staged expansion → disagreement design → abstention" and its evaluation against these baselines. This is a gap in what I read, not demonstrated novelty, and doc 24 shows the composition does not beat its simpler ablation.

## 4. Baselines implemented, executed and diagnosed
All see the same episodes (E0, E1 and the SWEEP_B schedule), the same IV-AR actuator model, the same skeleton from the u2-only episode, and one of three hidden-state front ends. Configurations were chosen on a **tuning namespace** (instance seeds 310–312, calib+dev families, never holdout); the full table is `results/ool_dev/baseline_tuning.json`.
* **PySR 2.7.2** — fixed library (+ − ×; square, cube, tanh) and expanded library (+ − × / max; square, cube, tanh, abs, sin, exp, sign, sqrt∘abs) fitted to the coupling drive φ = dx̂₂/dt + a x̂₂ − k u₂ with a tapped delay line (x₁, lags 1,3–9, x̂₂) as inputs; a raw-observation variant (role A) fits dx₃/dt with no latent. 40 iterations, 12 populations, ≤60 s per fit, `deterministic`, serial. Two development instances (thresh 0, 3) hung Julia and are missing (documented in doc 24); PySR was run only at B = 8 and 12.
* **SINDYc and weak-form SINDy** (pysindy 2.1.0, STLSQ): the whole x̂₂′ with controls [x₁, u₂ (, x₁ lags)]. Tuned best: degree-2 polynomial on (x₁, x̂₂, u₂), no lags, thresholds 0.02 (SINDYc) and 0.05 (weak): tuning median rollout RMSE 0.052 and 0.057.
* **Implicit SINDy**: pysindy 2.1.0 has `SINDyPILibrary` but no SINDy-PI optimizer, so I implemented the implicit/rational regression myself (STLSQ on [polynomial terms, φ·{x₁, x̂₂}]). It performs poorly (tuning median RMSE 1.76); this is a limitation of my implementation, not evidence about SINDy-PI.
* **Ridge NARX, Hammerstein static map** (from doc 20), **fixed-language structural search** (`L0`), **`static_all`**, and the privileged **oracle-structure** fit.
* **Tuned classical state reconstruction.** An RTS–Kalman smoother with the skeleton from E0 and the process-noise level q chosen by innovation likelihood: relative RMSE to the true hidden state 0.21 (untuned q = 4: 0.32; learned GRU: 0.11) on 18 tuning instances. Joint maximum likelihood over (a, b₃, k, q) was tried and **rejected**: it converges to a degenerate slow solution (a = 0.38, b₃ = 0.36) with a *higher* likelihood than the true parameters, because the unknown coupling is not white process noise — a model-misspecification pathology in classical estimation.

### Why nonlinear SINDYc diverged earlier (diagnosis)
Checked in this phase: (i) an **exactly structured** linear regression of the same target rolls out at RMSE 0.03, so the integrator and the state are not the cause; (ii) cubic libraries with ≥10 inputs (state, controls, lags) produce dense, collinear coefficients (cross terms up to ±16 for an exactly linear equation) that extrapolate badly; (iii) the Savitzky–Golay derivative of a Kalman-smoothed state is noisier (0.92) than the signal (0.29) at q = 4, and q-tuning halves the state error; (iv) tuning shows rollout RMSE of poly3/lag libraries 5–40 versus 0.05 for the degree-2 core library. The old divergence was therefore library size/collinearity plus derivative noise, not a numerical-integration instability (fixed-step integration with 4 substeps, clipping of the derivative at ±20 and a divergence flag |x₂| > 10³ never fired in the development run). RK45/LSODA were not run: not needed once the library was reduced.
